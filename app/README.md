# App Setup

## Тестовые пользователи

При первом запуске автоматически создаются два отладочных аккаунта:

| Роль  | Логин   | Пароль    |
|-------|---------|-----------|
| user  | `user`  | `user1234`  |
| admin | `admin` | `admin1234` |

Администратор может редактировать и удалять любые публикации.

## Базовые изображения

Чтобы при первом запуске в пустую галерею загрузились ваши фото, положите их в:

```text
backend/gallery/default_images/
```

Поддерживаются `jpg`, `jpeg`, `png`, `gif`, `webp`.

Команда `seed_default_images` запускается автоматически после миграций и создания тестовых пользователей. Она добавляет изображения только если галерея пустая, поэтому повторные запуски контейнера не создают дубликаты.

Для своих названий и описаний можно добавить рядом файл `manifest.json`:

```json
{
  "my-photo.jpg": {
    "title": "My Photo",
    "description": "Shown in the gallery after first launch."
  }
}
```

Минимальный набор команд перед началом работы с репозиторием.

## 1. Подготовить `.env`

Скопируйте пример и при необходимости поправьте значения:

```bash
cp .env.example .env
```

## 2. Установить git hooks

Нужно сделать один раз после клонирования репозитория:

```bash
make lint-install
```

## 3. Поднять инфраструктуру

Поднимает MongoDB и backend в Docker Compose:

```bash
make up
```

Остановить контейнеры:

```bash
make down
```

Полностью удалить контейнеры и volume базы:

```bash
make clean
```

## 4. Запуск проверок

Запустить pre-commit для файлов в `app/`:

```bash
make lint
```

## 5. Миграции

Сгенерировать миграции в Docker:

```bash
make migrations-docker
```

Сгенерировать миграции локально, чтобы файлы принадлежали вашему пользователю (приоритетно, требуется поднятая БД):

```bash
make migrations-local
```

Локальные миграции требуют запущенную MongoDB и используют `MONGO_HOST=localhost`.
